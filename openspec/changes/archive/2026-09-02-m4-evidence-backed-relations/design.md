## Context

M2 已有实体—片段共现链接，M3 已提供稳定证据 ID 和引用上下文。M4 需要在不引入图数据库的前提下，把可审核的一跳事实关系与共现候选分开。

## Goals / Non-Goals

**Goals:**

- 存储显式、推断和候选关系及其证据。
- 默认只展示审核通过且证据有效的关系。
- 支持实体关系卡片、审核更新和失效审计。

**Non-Goals:**

- 自动多跳推理、全自动事实抽取、交互式大图谱。

## Decisions

- SQLite 保存有向关系和多条稳定证据 ID。
- 受控 JSON 目录使用来源 ID + 原文片段选择证据，构建时解析为稳定 ID。
- `explicit` 至少一条证据且主客体都链接到证据；`inferred` 至少两条证据及推理说明。
- 共现只写入 `candidate/pending`，默认查询排除。
- 每次查询或审计确认稳定证据 ID 仍存在，失效关系不展示。

## Risks / Trade-offs

- 受控目录需要人工维护 → 保留候选发现与审核命令。
- 文本切分变化使证据 ID 更新 → 审计明确列出 stale 关系。
- 有向谓词可能需要反向展示 → 查询同时返回主体和客体方向。

## Migration Plan

新增关系表；导入首批审核关系；生成共现候选；运行审计与测试。关系表可从目录和实体链接重建。
