## Context

M2 返回带来源的候选片段，但没有“主张是否被引用真正支持”的执行层。第一版本需要离线可测，并允许未来接入任意草稿生成模型而不把信任交给模型。

## Goals / Non-Goals

**Goals:**

- 逐条验证主张与本次检索证据的绑定。
- 明确区分直接陈述、推理、不确定和冲突。
- 对证据不足问题稳定拒答。
- 引用可展开相邻上下文并返回官方链接。

**Non-Goals:**

- 追求自然语言文采、调用在线 LLM、完成多跳知识图谱。

## Decisions

- 证据 ID 由 provider、source external ID、document key 和 chunk key组成，避免数据库行号变化。
- 验证器接收结构化草稿，并只允许引用本次检索候选。
- `explicit` 主张采用规范化原文包含检查；默认生成器只抽取原句，因此可机械证明。
- `inferred` 至少绑定两条证据且必须携带推理步骤；标记为推理而非官方原话。
- `conflicted` 至少绑定两个不同来源或版本，并并列展示，不擅自裁决。
- 低于阈值或没有通过验证的主张返回 `uncertain`。

## Risks / Trade-offs

- 包含检查无法判断所有自然语言蕴含 → 首版默认只输出抽取式显式主张。
- 推理规则只验证结构完整性而非逻辑真实性 → 输出显著标记，并为后续蕴含模型保留接口。
- 数字行 ID 不稳定 → 对外只使用稳定证据 ID。

## Migration Plan

扩展检索结果字段但保留原 `chunk_id` 兼容性；新增 QA 模块和 `ask` 命令。失败时可独立移除 QA 层，不影响 M1/M2 数据和检索。
