# Explore: M3 受证据约束的问答

## 核心问题

检索命中并不等于结论成立。若让模型直接阅读片段并自由回答，它仍可能补入未检索记忆、错误归因、混淆宣传语境，或给整段答案附上一组无法对应到具体主张的链接。

## 可选边界

- 只靠提示词要求引用：无法程序化验证，不采用为可信边界。
- 使用外部 LLM 做生成和验证：验证器与生成器可能共享幻觉，且本地测试不可复现。
- 结构化主张 + 确定性验证：能强制证据 ID、主张类型和最小支持规则，采用。
- 默认抽取式回答：自然度有限，但原文包含关系可机械验证，适合作为首个安全基线。

## 状态模型

```text
检索低于阈值 ───────────────→ uncertain / 拒答
        │
        └→ 草稿主张 → 证据白名单 → 类型规则 → 支持检查
                                             │
                          通过 ───────────────┤→ 输出
                          失败 → 删除或降级 ──┘
```

## 结论

证据使用稳定 ID，不依赖会在重解析后变化的 SQLite 行号。显式主张必须可在单条证据中找到；推理主张至少需要两条证据和可展示推理步骤；冲突主张必须包含两个不同来源或版本；所有失败主张记录拒绝原因。
