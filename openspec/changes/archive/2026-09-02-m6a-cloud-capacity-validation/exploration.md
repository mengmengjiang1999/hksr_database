# Explore: M6A 中国大陆云容量验证

## 目标边界

第一轮语料限定为主线剧情、角色资料、阅读物和关键官方视频。M6A 只验证容量、技术选型和迁移边界，不购买云资源、不上传语料、不修改线上系统。

## 当前真实样本

- 5 个来源、15 个文档、41 个片段、17,426 个字符；
- 原始响应共约 377 KiB，本地 SQLite 数据库约 2.93 MiB；
- 当前字符 n-gram 稀疏向量以 JSON 保存，41 条向量约占 1.34 MiB，不能直接作为生产容量模型；
- 角色样本约 208,906 字节原始响应、9,805 字符、23 个片段；
- 主线任务样本约 138,013 字节原始响应、6,951 字符、15 个片段；
- 阅读物样本约 12,340 字节原始响应、349 字符、1 个片段；
- 视频样本约 10,247 字节原始响应、156 字符、1 个片段。

## 官方目录规模（2026-09-02）

- 角色：98；
- 阅读物：652；
- 开拓任务：214，开拓续闻：49，主线口径合计 263；
- 关键视频口径：角色 PV 58、千星纪游 PV 27、角色解说 70、版本 PV 33、动画短片 18、剧情 CG 63，合计 269。

按样本直接外推约 7,120 个当前版本片段。考虑文本长度偏差、切分策略变化和历史版本，容量验证采用 10,000、50,000、100,000 三档，并保留 1,000,000 片段作为拆分专用向量服务的观察线。

## 架构发现

- 大型原始响应和版本快照适合对象存储，不适合全部进入关系数据库；
- PostgreSQL 保存来源、文档、片段、实体、关系、证据和同步状态；
- 阿里云 RDS PostgreSQL 当前支持 pgvector，并提供 `zhparser`、`pg_jieba`、`pg_bigm` 等中文检索插件，但具体版本和规格必须在采购前核验；
- OSS 支持版本控制；RDS 支持自动备份和时间点恢复；
- 第一轮规模不足以证明需要 AnalyticDB、Elasticsearch、独立向量数据库或图数据库。

## 风险和未知项

- 一个角色、任务和阅读物样本不足以给出统计置信区间，外推必须标为规划估算；
- 官方目录条目和分类会随版本更新；
- 视频官方字幕覆盖仍不稳定，不能把自动语音识别文本标作游戏内原文；
- 云产品价格动态变化，M6A 只给资源规格、计费项和预算门槛，采购时使用官方询价结果；
- 中国大陆公网服务后续还需单独处理备案、安全、内容授权和访问控制。

## Explore 结论

采用“OSS 为不可变原始层、RDS PostgreSQL 为事实主库、pgvector 为第一阶段向量索引”的单区域架构。M6B 只有在实测超过 100,000 片段或查询指标不达标时，才比较 AnalyticDB PostgreSQL 或独立向量数据库。
