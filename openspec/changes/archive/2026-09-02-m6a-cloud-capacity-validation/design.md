## Context

本地数据库只含 5 个验证来源，SQLite 文件大小又受到 JSON 稀疏向量实现影响，不能直接外推生产云容量。部署区域确定为中国大陆，第一轮内容仅包含 98 个角色、263 个主线任务、652 篇阅读物和约 269 个关键视频目录项。

## Goals / Non-Goals

**Goals:**

- 从本地真实文件和数据库读取可复现的容量基线；
- 用显式目录数量和样本均值生成保守外推；
- 对标准 1024 维向量的 float32、halfvec 和 HNSW 规划容量；
- 给出中国大陆单区域最小架构、数据分层、备份和升级门槛。

**Non-Goals:**

- 不抓取第一轮全部正文；
- 不购买或基准测试真实 RDS；
- 不迁移 SQLite 业务代码；
- 不确定最终云产品价格；
- 不部署公网应用。

## Decisions

1. **容量报告必须由程序生成。** 手写结论容易随样本变化而失效；工具读取数据库、原始目录和配置化目录数量，输出稳定 JSON。
2. **分开测量与估算。** 报告中的 `measured` 只能来自磁盘和 SQL；`projection` 必须标出样本均值、倍数和不确定性。
3. **生产向量按稠密二进制估算。** 当前 n-gram JSON 仅作为本地原型实测，不用于 RDS 选型。1024 维 float32 为每向量 4,104 字节，halfvec 为 2,056 字节；HNSW 规划采用向量本体的 1.5 倍保守系数，最终以云上 `pg_total_relation_size` 校准。
4. **使用三档采购情景。** 10k 是首轮预期，50k 是历史版本与扩展余量，100k 是单库验收上限；1M 只用于触发架构复核。
5. **OSS + RDS PostgreSQL 为推荐基线。** OSS 保存不可变原始版本，RDS 保存事实、文本和向量；避免在规模未证明前引入 AnalyticDB、Elasticsearch 或独立向量库。
6. **云费用只记录计费项和预算门槛。** 动态折扣和地域价格必须在采购日通过官方询价确认，不能固化为事实价格。

## Risks / Trade-offs

- [样本量小且各条目长度差异大] → 同时给直接外推和 2×、5×、10×安全情景，M6 全量抓取后重新运行。
- [HNSW 实际大小依赖维度、参数和版本] → 估算只用于选规格，真实云 PoC 必须测 `pg_total_relation_size`、召回和延迟。
- [中文插件随 RDS 版本和规格变化] → 采购清单要求执行 `pg_available_extensions` 验收。
- [原始资料误公开] → OSS Bucket 默认私有、同地域内网访问、开启版本控制和最小权限。
- [单区域故障] → 第一轮使用 RDS 自动备份/PITR 和 OSS 版本控制；正式公网版再决定跨区域恢复目标。

## Migration Plan

M6A 只交付报告。后续 M6B 创建隔离测试 VPC、私有 OSS Bucket 和测试 RDS，先导入脱敏/公开样本，验证扩展、容量、性能、备份恢复；失败时删除测试资源并继续使用本地 SQLite，不影响当前 Demo。
