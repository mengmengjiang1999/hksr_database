# M7 之后的阶段路线图

> 状态：2026-09-04 更新。M7 后台采集与 M9 问答开发并行，各阶段以验收条件而不是日期为准。

## 目标

M7 已在 ECS 上建立米游社官方账号与 Wiki `游戏图鉴` 的私有采集链路。由于完整 Wiki 采集耗时较长，产品开发不再完全等待采集结束：采集继续补齐语料，实体建模、真实问题评测、意图检索和证据型自然回答同时推进。

```text
M7 米游社与 Wiki 采集入库（后台持续）
  ├── M8 私有只读 UI 基础（已完成）
  └── M9 实体感知的证据问答（下一阶段）
        → M10 RDS 正式读取与全量质量评测
        → M11 云端产品完善
        → M12 受控开放与长期运维
```

开发与离线测试可在本地完成；真实采集、云端集成测试和部署在 ECS 上进行。M7 的请求限速、OSS 持久化和监控不因 M9 开发而改变。

## M8：私有只读 UI 基础

状态：已完成。

已交付问答、证据检索、来源详情和资料覆盖页面，并固定浏览器依赖的只读 API 契约。当前 ECS 应用仍读取 SQLite 暂存库；RDS 正式读取适配移至 M10，不把基础界面交付阻塞在数据库切换上。

## M9：实体感知的证据问答

目标：让系统区分剧情人物与实机形态、理解常见问题意图，并根据当前已收录的官方证据给出自然、直接且可校验的回答。

主要工作：

- 分离剧情人物、实机角色形态、官方别名、标点变体和玩家术语；
- 以“姬子 / 姬子·启行”为首个固定回归案例：实机是两个角色形态，剧情身份是同一人物；
- 建立 50 至 100 条真实问题集，覆盖身份、形态、关系、获取方式、时间、描述、比较和无答案问题；
- 将失败区分为语料缺失、解析错误、实体歧义、意图错误、排序遗漏、生成失败和正确拒答；
- 对关系问题保留两个实体端点，要求证据覆盖双方或命中已审核关系；
- 接入可替换的受约束模型接口，只接收本次检索证据并输出结构化主张与证据 ID；
- 使用确定性程序验证每条主张，模型关闭、超时或输出无效时退回模板或原文摘录；
- 在 API 和私有 UI 中展示直接答案、实体解析、歧义、部分回答、生成状态和逐条引用。

完成标准：真实问题集能够输出直接答案、透明的部分答案或正确拒答；事实性主张引用覆盖率为 100%；无证据事实不会因模型记忆进入回答；模型不可用时基础问答仍可使用。

详细实施计划见 OpenSpec change `m9-entity-aware-grounded-qa`。

## M10：RDS 正式读取与全量质量评测

目标：让 ECS 应用使用 RDS 正式数据，并验证 M9 的实体、检索和回答逻辑在扩充后的真实语料上仍然可靠。

主要工作：

- 将来源、片段、实体、关系和证据查询切换到 PostgreSQL；
- 在 RDS 建立全文、实体和必要的向量索引，同时保持现有 API 契约；
- 记录语料快照指纹并在完整问题集上重新评测；
- 统计 Top 5 证据召回率、直接答案正确率、引用覆盖率、拒答准确率和错误类型；
- 优先修复数据缺失、切分、实体歧义和版本混用，再调整排序参数；
- 完成 SQLite/RDS 结果对照、性能抽样和可重复部署命令。

完成标准：ECS 应用只依赖 RDS 即可完成现有浏览与问答；核心问题 Top 5 证据召回率达到 85% 至 90%；事实主张均有有效引用；无答案问题能够稳定拒答；主要失败类型均有明确记录。

## M11：云端产品完善

目标：把通过质量验收的能力整理成便于持续使用和维护的私有云端产品。

主要工作：

- 完善人物、形态、任务、来源、关系和人工审核页面；
- 增加采集批次、错误任务、待审核内容、模型用量和成本状态；
- 配置身份验证、HTTPS、日志轮转、健康检查和最小权限；
- 建立可重复的 ECS 测试、迁移、部署和回滚流程；
- 根据真实使用记录 ECS、RDS、OSS 和模型成本。

完成标准：授权用户可以稳定使用云端界面，维护者能够查看数据与问答状态、处理审核项并完成可重复部署。

## M12：受控开放与长期运维

目标：在数据质量和私有运行稳定后，再决定是否扩大访问范围以及是否启用长期自动同步。

主要工作：

- 先进行少量受邀用户测试，收集真实问题和失败案例；
- 评估官方内容展示、缓存和再分发边界；
- 经明确批准后启用定时增量采集，并持续观察限流与失败；
- 建立基础告警、容量趋势、模型用量和月度成本记录；
- 根据实际连续用量决定 ECS/RDS 的长期计费方案。

完成标准：访问范围、内容边界、更新频率、费用方案和日常维护责任均有明确决定。

## 推荐优先级

1. M7 保持后台运行并由现有半小时监控跟踪。
2. 立即实施 M9 的真实问题基线和人物/形态模型，不等待全量 Wiki。
3. 先交付确定性意图与直接答案，再启用可选的受约束模型试验。
4. 语料覆盖充分后进入 M10，切换 RDS 并冻结最终质量阈值。
5. M11 和 M12 仅在问答与数据质量验收后推进。

备份恢复演练暂不作为这些阶段的门槛，除非以后进入多人使用、正式开放或更高数据安全等级。
