# M3 受证据约束问答实施报告

> 状态：本地确定性闭环完成
>
> 日期：2026-09-02

## 1. 阶段结论

M3 已实现从玩家问题到主张级引用回答的可信边界：

```text
问题 → M2 检索 → 结构化主张草稿 → 证据白名单
                                      ↓
                         主张类型和支持规则验证
                                      ↓
                    通过：逐条引用 / 失败：删除或拒答
```

默认回答器不调用大模型，只从最高排名的官方证据中抽取原句，因此不会补入模型记忆。未来模型只能作为“草稿生成器”接入，最终输出仍必须通过同一个确定性验证器。

## 2. 核心保证

### 2.1 稳定证据 ID

对外证据 ID 由以下稳定字段组成：

```text
provider : source external_id : document_key : chunk_key
```

SQLite 行 ID 在强制重解析后会变化，稳定证据 ID 不变。引用不会因为正常重建数据库而失效；官方内容或切分规则变化时，片段哈希改变，证据 ID 也会相应变化。

### 2.2 本次检索边界

验证器只接受当前问题检索结果中的证据 ID。即使草稿引用了数据库中真实存在、但本轮没有检索到的片段，也会以 `evidence_not_retrieved` 拒绝。

### 2.3 四种结果

| 类型 | 验证规则 | 默认回答器是否自动生成 |
| --- | --- | --- |
| `explicit` | 主张规范化后必须完整出现于至少一条引用原文 | 是 |
| `inferred` | 至少两条本轮证据，并提供非空推理步骤 | 否，只验证外部草稿 |
| `uncertain` | 检索低于阈值或没有主张通过验证 | 是 |
| `conflicted` | 至少两个不同来源或版本，且每个备选说法受对应原文直接支持 | 否，只验证外部草稿 |

`inferred` 当前只完成结构和证据链验证，不能证明推理逻辑本身正确，因此返回 `support_check: structural_only`，并且必须显式标记为推理。

### 2.4 主张级引用

每个通过的事实主张独立携带引用，引用包括：

- 稳定证据 ID；
- 官方原文；
- 来源标题、类型和官方状态；
- 栏目路径和明确说话人；
- 版本与语境；
- 原始官方页面链接；
- 同一文档前后各一个证据块。

## 3. CLI

直接提问：

```bash
python3 -m app.cli ask "小三月的纯真有没有失去？"
```

只允许游戏内语境：

```bash
python3 -m app.cli ask "真珠的母题是什么？" --context in_game
```

调整拒答阈值：

```bash
python3 -m app.cli ask "问题" --minimum-score 0.22
```

运行问答评测：

```bash
python3 -m app.cli evaluate-qa
```

## 5. 限制

- 默认输出是官方原文摘录，不是经过润色的自然语言回答；
- 当前没有接入 LLM，推理和冲突需要外部结构化草稿触发；
- 显式支持采用规范化字符串包含规则，无法验证同义改写；
- 推理验证只能保证引用数量和推理步骤完整，不能判断逻辑蕴含；
- 18 条评测仍是小样本，不能代表完整语料；
- 拒答阈值需要随数据量扩大重新校准。

M4 可以在此可信边界上建设带证据的一跳关系；任何关系卡片仍应绑定稳定证据 ID，不得由共同出现直接升级为确定关系。
