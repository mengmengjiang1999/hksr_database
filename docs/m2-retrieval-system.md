# M2 本地检索系统实施报告

> 状态：首批样本闭环完成
>
> 日期：2026-09-02

## 1. 阶段结论

M2 已在当前五个官方来源上完成“问题 → 候选证据”的本地闭环：

```text
玩家问题
  ↓
实体及别名识别
  ↓
中文字符全文匹配 + 本地语义相似度
  ↓
实体、来源质量、栏目相关性加权
  ↓
来源类型 / 版本 / 语境过滤
  ↓
带评分解释和原始页面定位的证据列表
```

本阶段不生成自然语言答案，也不允许检索器把相关片段直接解释成事实。它只负责返回可能支持答案的官方证据。

## 2. 已实现能力

### 2.1 实体与别名

SQLite 新增 `entities`、`aliases` 和 `entity_chunks`：

- 首批录入 35 个角色、阵营、地点、星神、命途、事件、物品和任务实体；
- 共 45 个规范名及别名；
- 实体匹配同时检查来源标题、栏目路径和正文；
- 玩家俗称标记为 `player`，只用于理解问题，不作为扩展后的官方证据文本；
- 当前 41 个片段产生 243 条实体—证据链接。

实体表是可审查的本地清单，位于 `data/m2/entities.json`。当前阶段不使用大模型自动创造实体或关系。

### 2.2 本地语义索引

为避免第一版本依赖在线嵌入接口，语义基线采用字符 2/3/4-gram TF-IDF：

- 向量完全在本地生成；
- 适用于没有空格的中文文本；
- 能处理部分同义改写和原文措辞差异；
- 向量与 IDF 元数据保存在 SQLite；
- 重新运行 `index` 会完整、幂等地重建。

该方案是可复现基线，不等同于神经网络 embedding。数据规模扩大后，可在保持检索接口不变的情况下替换成本地嵌入模型。

### 2.3 混合排序

默认排序组合以下信号：

- 中文字符词面覆盖率；
- TF-IDF 余弦相似度；
- 问题实体与片段实体的匹配比例；
- 实体是否位于来源标题或栏目路径；
- 官方来源类型的质量权重。

每条结果返回 `score_components`，因此可以看到命中来自词面、语义还是实体，而不是只得到不可解释的总分。

支持三种模式：

- `lexical`：词面基线；
- `semantic`：本地语义基线；
- `hybrid`：默认混合排序。

### 2.4 过滤与追溯

检索支持按以下条件过滤：

- `source_kind`；
- Wiki 版本；
- `in_game`、`official_supplement`、`promotional` 等语境。

结果继续保留来源 ID、官方状态、页面链接、栏目路径、说话人和片段正文。过滤在排序前执行，避免不符合要求的资料进入候选集。

### 2.5 对话结构

- 默认片段上限从 800 字收紧到 500 字；
- 对 `角色：台词` 形式的明确说话人进行确定性提取；
- 不根据上下文猜测省略的说话人；
- 说话人字段同时进入全文和混合检索。

## 3. CLI

重建全部检索索引：

```bash
python3 -m app.cli index
```

混合检索：

```bash
python3 -m app.cli search "小三月的纯真有没有失去？" --limit 5
```

限定为游戏内语境：

```bash
python3 -m app.cli search "真珠的母题是什么？" --context in_game
```

比较检索模式：

```bash
python3 -m app.cli search "阿格莱雅的寄语如何获得？" --mode lexical
python3 -m app.cli search "阿格莱雅的寄语如何获得？" --mode semantic
```

运行标注集评测：

```bash
python3 -m app.cli evaluate
python3 -m app.cli evaluate --mode lexical
python3 -m app.cli evaluate --mode semantic
```

## 4. 初始评测

标注集位于 `data/m2/evaluation.json`，包含 36 个问题：

- 33 个可回答问题；
- 3 个当前知识库无法回答的问题；
- 覆盖角色 Wiki、阅读物、任务、官方视频简介和官方文章；
- 每个可回答问题标注官方来源 ID 和应出现的证据文本。

| 模式 | Top 1 | Top 5 | 无答案识别 |
| --- | ---: | ---: | ---: |
| 词面 | 84.85% | 90.91% | 66.67% |
| 本地语义 | 75.76% | 100% | 100% |
| 混合 | 87.88% | 100% | 100% |

混合检索达到规划中的 85% 至 90% Top 5 门槛，并且较两条单独基线取得更高的 Top 1。词面基线会对一个无答案问题产生高分误召回，说明拒答不能依赖单一词面信号。结构化结果保存于 `data/m2/validation-report.json`。

## 6. 限制与下一步门槛

当前结果不能外推到完整游戏知识库：

- 数据仅有 5 个来源、41 个证据片段；
- 36 个问题与当前样本来自同一小范围，难度有限；
- 无答案样本只有 3 个，阈值尚未充分校准；
- TF-IDF 对跨句推理和深层同义改写能力有限；
- 说话人只提取显式标签，不推测被省略的发言者；
- 实体清单仍由人工维护，尚未覆盖同名消歧和版本化别名。

进入 M3 前，建议先扩充到至少 500 个有效片段，并把评测集扩展到约 100 个问题。M3 可以先基于当前检索接口开发主张级证据绑定，但不能把本次小样本的 100% Top 5 当作全量质量承诺。
