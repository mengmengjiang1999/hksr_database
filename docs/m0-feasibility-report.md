# M0 数据采集可行性报告

> 状态：已完成第一轮探测
>
> 日期：2026-09-02
>
> 范围：官方 Wiki、阅读物、任务、官方文章、官方视频

## 1. 结论

M0 的基础数据方案可行。官方 Wiki 详情、Wiki 搜索、米游社官方账号文章列表和文章详情均存在浏览器正在使用的结构化 JSON 接口。第一版不需要以浏览器 DOM 抓取作为主要采集方式。

五类样本中，角色、阅读物、任务和官方文章均可直接提取机器可读正文；官方视频可以提取官方发布身份、标题、简介、视频 ID、时长和清晰度元数据，但样本接口未提供独立的机器可读官方字幕。因此，视频“资料发现与元数据采集”可行，“完整台词自动进入文字证据库”暂时属于有条件可行。

按照规划中“至少四类能够稳定提取正文、来源链接和必要上下文”的门槛，M0 可以通过并进入 M1。但 M1 第一批数据应以 Wiki 文本和官方文章为主，视频先保存元数据和官方简介。

## 3. 已确认的数据接口

### 3.1 Wiki 词条详情

```text
GET https://act-api-takumi-static.mihoyo.com/common/blackboard/sr_wiki/v1/content/info
    ?app_sn=sr_wiki
    &content_id={content_id}
```

返回内容包括：

- 词条 ID、标题、摘要；
- 创建时间、修改时间和词条版本；
- 频道分类；
- RPG 专用模板数据或普通页签 HTML；
- 模块名称、组件类型和正文；
- 图片、音频及关联词条元数据。

页面本身只返回 Nuxt 应用外壳，正文由前端调用该接口加载。因此应优先使用结构化接口，浏览器 DOM 只用于接口变化后的诊断和人工核对。

### 3.2 Wiki 搜索

```text
GET https://act-api-takumi.mihoyo.com/common/blackboard/sr_wiki/v1/search/content
    ?app_sn=sr_wiki
    &keyword={keyword}
    &page={page}
    &page_size={page_size}
```

搜索结果同时包含 Wiki 词条和米游社文章，并提供标题、摘要、频道和目标链接。该接口适合关键词发现和补充关联来源，但不适合单独完成全量同步；M1 仍需继续验证频道列表和分页发现接口。

### 3.3 官方账号文章列表

```text
GET https://bbs-api.miyoushe.com/painter/wapi/userPostList
    ?size={size}
    &uid=288909600
```

返回分页游标、文章、用户认证、视频和图片元数据。必须验证每条结果中的官方账号认证，不能只因为它来自某个列表 URL 就直接进入证据库。

### 3.4 米游社文章详情

```text
GET https://bbs-api.miyoushe.com/post/wapi/getPostFull
    ?gids=6
    &post_id={post_id}
    &read=1
```

该接口需要普通浏览器 `User-Agent`，并应携带米游社 `Referer` 和 `Origin`。不携带这些请求信息时，实测可能返回 HTTP 403。

文章详情可以验证：

- `post_status.is_official`；
- 发布账号及官方认证标签；
- 标题、正文、发布时间和更新时间；
- 论坛分类、主题和关联图片；
- 视频 ID、时长、清晰度和编码信息。

## 4. 页面结构差异

Wiki 至少存在两条解析路径：

### RPG 模板

角色词条使用 `rpg_new_tmp_content`，包含 `base`、`modules`、`tabs` 和 `type`。模块组件的 `data` 通常还是一层 JSON 字符串，需要二次解码。

模块中同时包含剧情资料、游戏数据和攻略推荐。解析器必须按模块名称和组件类型进行白名单及黑名单分类，不能将整份角色数据直接放入剧情证据库。

### 普通页签模板

阅读物和任务样本使用 `contents[].text` 保存 HTML。HTML 中常带有 URL 编码的模板数据，也包含最终渲染正文。第一版可以从渲染 HTML 提取文本，同时保留页签、表格和段落顺序；后续再评估是否优先解码模板数据以获得更精确的字段。

## 5. 官方身份验证

米游社搜索结果可能同时包含官方资料和玩家内容。正式采集时至少验证：

1. 文章状态中的 `is_official`；
2. 用户认证标签包含官方账号标识；
3. 游戏 ID 为《崩坏：星穹铁道》；
4. 保存发布账号 UID 和认证文本；
5. 更新时重新验证官方状态。

当前验证的官方账号 UID 为 `288909600`。该值可以作为发现入口，但不能替代逐篇官方身份校验。

## 6. 视频与字幕限制

官方视频文章能够返回视频 ID、时长、封面和多清晰度播放信息，但样本响应未发现独立字幕或 caption 字段。播放地址带临时签名，不能作为持久标识保存。

M1 建议：

- 持久保存文章 ID、视频 ID、标题、官方简介和页面链接；
- 不持久保存临时签名视频地址；
- 暂时只将官方简介作为文字证据；
- 视频画面和对白仍可作为官方证据源，但需要引用视频 ID 和时间戳；
- 自动语音识别结果属于派生文本，必须经过人工核对后才能作为可搜索的证据转录；
- 在字幕来源方案确定前，不承诺对视频完整内容进行文本问答。

## 7. 可重复探测工具

执行测试：

```bash
python3 -m unittest discover -s tests -v
```

执行在线探测：

```bash
python3 -m app.m0_probe
```

探测结果默认写入 `data/m0/latest-probe-report.json`。报告只保存：

- 接口响应哈希和字节数；
- 来源元数据；
- 页面布局和模块清单；
- 可提取文本的数量统计；
- 官方身份和视频/字幕能力标记。

报告不保存完整官方正文，也不下载视频、图片或音频。

## 8. M0 通过条件

M0 探测程序使用以下最低门槛：

- 五个来源样本中至少四个通过；
- Wiki 搜索发现通过；
- 官方账号列表发现通过；
- 官方文章必须通过官方身份校验；
- 每个通过的文字来源都能提取非空文本并保留来源 ID；
- 输出中不得依赖临时视频播放 URL 作为持久标识。

## 9. M1 前置任务

进入 M1 后优先完成：

1. 建立 `Source`、`Document`、`Chunk` 三张核心表；
2. 将 RPG 模板和普通页签拆成两个解析器；
3. 建立栏目白名单、黑名单和未知栏目隔离区；
4. 实现 Wiki 频道分页发现，而不只依赖关键词搜索；
5. 实现官方账号文章游标分页；
6. 保存来源版本、响应哈希和更新时间；
7. 为解析器建立不含大段官方正文的最小化回归样本；
8. 单独研究视频字幕、时间戳证据和人工核对流程。

## 10. 风险

- 当前接口由站点前端使用，但未观察到面向第三方的稳定性承诺，字段和地址可能变化；
- Wiki 页面包含编辑团队原创内容及转载限制，公开在线版需要额外合规评估；
- 官方账号文章接口存在请求头限制和潜在频率限制；
- 页面中的攻略、宣传表达、开发中内容与游戏内正式文本必须保持语境隔离；
- 本报告只验证技术可行性，不等同于授予转载、公开分发或批量抓取许可。
